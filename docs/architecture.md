# Proposed architecture

The Apple Silicon macOS release uses AppKit. Rocky Linux is the next portability target, with Windows possible later. Keep the interaction rules, model catalog, and audio timeline portable. Ship one English voice and one selected English-capable Whisper checkpoint.

## Stack

| Choice | Recommendation and tradeoff |
| --- | --- |
| Portable logic | Prefer Rust for the interaction session, model library, and reading timeline. Keep Core Audio, accessibility, window management, and process details outside the portable package. Rust supports the major macOS, Linux and Windows targets. Shipping support still depends on testing each platform's adapters. [Rust target support](https://doc.rust-lang.org/rustc/platform-support.html) |
| Desktop | Use a nonactivating AppKit `NSPanel` with native controls and text editing. Swift owns the AppKit lifecycle and calls the Rust session over a narrow C interface. Apply the same native focus, accessibility, latency and idle gates to the actual app. [AppKit panel focus](https://developer.apple.com/documentation/appkit/nspanel/becomeskeyonlyifneeded) |
| Speech | Start with whisper.cpp on Apple Silicon Metal. Compare the released `small.en`, `medium.en-q5_0` and `large-v3-turbo-q5_0` GGML artifacts. Pair the winner with a complete Kokoro ONNX pipeline. Test native sherpa-onnx with an offline English frontend first. Compare a Kokoro duration-output ONNX export if native frontend quality or phrase prosody misses the gate. [whisper.cpp](https://github.com/ggml-org/whisper.cpp) [GGML artifacts](https://huggingface.co/ggerganov/whisper.cpp/tree/main) [sherpa Kokoro](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html) [Kokoro ONNX releases](https://github.com/thewh1teagle/kokoro-onnx/releases) |
| Build | One macOS app target, a portable Rust package, one child executable that can run in either engine role, and an independent test runner. Pin the compiler, SDK, webview host if selected, and native runtime revisions before acceptance. Sign the app with a stable identity for permission tests. |

Rocky can reuse the session and speech implementation and render the same interaction contract with a Linux host. Its shortcut and external text adapters remain desktop-specific. A future Linux UI can consider Tauri after checking WebKitGTK availability and the Wayland shortcut path. [Tauri RPM requirements](https://v2.tauri.app/distribute/rpm/) [Global hotkey platform support](https://github.com/tauri-apps/global-hotkey)

Keep C/C++ inference calls inside the child executable. Benchmark one worker with two models against two engine children built from that same executable. Start with two if they meet the warm idle budget. This lets a stuck reading job be terminated without evicting Whisper. Both children exit on automatic offload. Compare against in-process inference during calibration if child startup or data copying harms responsiveness.

## Module ownership

| Module | Owns | Verification at its interface |
| --- | --- | --- |
| Interaction session | Draft and caret revisions, invocation and task identity, requests for capture or playback, completion and recovery, the idle deadline | Send user intents, clock changes, and adapter outcomes. Inspect view state and attributed effects. No app window or live model required. |
| Desktop adapter | Shortcut and focus observations, reading the live selection, capturing an external destination, performing one validated edit | Run a controlled adapter for races and use the macOS adapter against real browsers and TextEdit. Record confirmed, rejected, and indeterminate outcomes. |
| Reading transport | Phrase ranges in the session's reading snapshot, committed audio frames, playing or paused intent, one pending seek, and the presentation clock | Assert the audible frame, slider, and highlight point to the same phrase. Keep this inside the speech/playback implementation unless another caller needs it. |
| Speech runtime | Readiness, worker lifetime, incremental inference and cancellation, bounded IPC, reaping of failed children | Exercise ready, unavailable, timeout, and result outcomes through the session. Measure actual microphone, audio, CPU and footprint independently at the packaged app. |
| Model library | Catalog, compatibility, resolved local assets, file verification, discovery and transactional installs/removal | Exercise setup and Settings against temporary directories and a controlled download source. Production downloader and controlled source justify the seam. |
| Capsule and settings | Rendering, native editing, accessibility and preferences input | Test the same user actions and controls users see. Bind controls to session intents. The views own no speech policies. |

Apply the deletion test. Without the interaction session, each button and callback would coordinate a different view of focus, draft, and audio. Without the model library, setup, Settings and preload would disagree about local file validity. A separate global event bus, a plugin registry, and a module per button would add callers with no ownership gain. Treat temporary platform probes as experiments. Keep their code out of the shipping app.

### Session and lifecycle

- Use one serialized owner for the interaction session. Represent one speech task as reading, dictating, or absent. Represent reading transport, reading view, and capsule visibility separately, because a paused reading can have any playback view. Carry a task identity with every asynchronous outcome. Only its matching live task may change output.
- Opening the capsule requests both models. A fast Read Aloud click captures the source immediately, then waits for that request's model. An authorized mic click opens capture while Whisper warms and retains the first samples in a bounded memory queue. Final ASR text comes from accepted chunks of the take. A provisional transcript can be revised. Pause closes capture. Escape stops output or cancels capture and invalidates late results.
- The session starts one idle deadline when hidden with no pending speech action. Preload alone cannot keep the deadline alive. Reopening cancels it. At expiry, invalidate old generations, clear the draft and ephemeral data, then request worker termination. Ignore an old termination acknowledgement after a new generation opens. Keep Loaded suspends expiry. A crash cannot reopen the microphone or replay a delivery.
- Let one native audio clock drive playback. Generate ordered phrases with exact source spans. Append actual PCM frame counts to the timeline. Clicks and the slider use that timeline. An ungenerated click creates one pending target and pauses output. Finish generation through that target, then honor the most recent target and the user's pause intent. The slider remains constrained to generated time. Test joins for unnatural pauses and verify the source span around punctuation, abbreviations and Unicode.
- Default to **30 minutes of generated reading** and **10 minutes of captured dictation**. Store the two preferences independently and snapshot them when a task starts. At 24 kHz with signed 16-bit mono samples, 30 minutes of audio occupies about 82 MiB. Ten minutes of 16 kHz mono input takes about 18 MiB. Validate upper limits in Settings against measured active memory and cancellation time, and bound in-flight work separately. At the cap, keep generated reading seekable and keep captured dictation available for Finish. A proposed 10-second pre-ready buffer holds early input and must fail visibly before discarding samples.
- The optional microphone check uses the same capture and recognition path as normal dictation, with a separate destination for its temporary result. Allow skipping it during setup and opening it later in Settings. Stop capture on cancel, display the local preview, then clear test audio and text when the check closes. Collecting retained recordings or adapting a model is a separate future feature.

### Desktop capability

Start with public Accessibility attributes and the browser's focused document or field. Capture the dictation destination at the mic click. Give the draft priority when its editor has keyboard focus. Determine the live external selection at each new Read Aloud. Handle a genuine empty selection separately from an unavailable query. Keep the passive overlay focus test separate from the draft editor taking keyboard focus.

On confirmation after transcript review, the desktop adapter verifies the original app, window, field, text value and selected range before one edit. Native fields that support selected-text replacement use Accessibility. Editable browser fields use their standard Paste command when clipboard access is available. Immediately before dispatch, AHAMPO checks focus and verifies its marker on the temporary clipboard item. It checks the resulting text before confirming insertion. Cancellation before dispatch prevents the edit. A dispatched edit may finish while its result is being verified, and an uncertain result keeps a recoverable transcript. The app makes one attempt. [Apple AX attributes](https://developer.apple.com/documentation/applicationservices/carbon_accessibility/attributes) · [Apple AX writes](https://developer.apple.com/documentation/applicationservices/1460434-axuielementsetattributevalue)

Some Gecko controls fail to report an untouched caret. An empty field has only one insertion position. A populated field requires an observable range. AHAMPO retains the transcript separately when a focused field cannot be verified, so existing draft text is not edited as a side effect. Clipboard restoration checks the temporary marker and change count. macOS provides no atomic conditional restore, so the checks reduce the concurrent-write window and preserve a detected later clipboard change. [Firefox implementation](https://github.com/mozilla-firefox/firefox/blob/main/accessible/mac/mozTextAccessible.mm) · [Apple pasteboard access behavior](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum/default)

Reading falls back to the draft directly on the speaker click. The macOS adapter can use scoped Copy to verify Gecko page selections or read an otherwise unreadable selection with a positive range in an editable field. It requires existing clipboard access. Failed external dictation retains the transcript for **Copy** or **Insert into Draft**. Place global registration, microphone permission prompts, screen placement and OS window behavior in the macOS adapter. Future Rocky work starts with the actual Wayland/X11, portal and AT-SPI capabilities of the target desktop. [Wayland GlobalShortcuts portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) [AT-SPI EditableText](https://docs.gtk.org/atspi2/iface.EditableText.html)

## Shared model library

Use `~/Library/Application Support/Local Speech Models` as the proposed default macOS folder. Keep it per-user and writable without admin access. A later Linux adapter could use the XDG user-data location. Settings shows the effective folder and the resolved path and format of each asset set. Another app can be pointed at the same files if its runtime accepts them. Whisper GGML, Whisper Core ML, Kokoro PyTorch and Kokoro ONNX are different formats. Even two ONNX exports can use different layouts or require different voice files. [XDG directories](https://specifications.freedesktop.org/basedir/latest/) [Kokoro upstream model files](https://huggingface.co/hexgrad/Kokoro-82M/tree/main) [Hugging Face cache layout](https://huggingface.co/docs/huggingface_hub/en/guides/manage-cache)

- Catalog a stable asset identity, capability, language, version, runtime format, byte count, source revision, SHA-256, every required companion file, and license notice. Start with two installable asset sets. Model loading consumes a verified local asset set. It doesn't run a dependency resolver or a download.
- Search the selected folder first, then paths the user approves. Propose recognizing compatible existing GGML files and the supported Kokoro layout, including pinned files in a configured Hugging Face cache. Use an exact compatible set in place. Never recopy it simply because it lives outside the selected folder. If several match, use the user's explicit choice or deterministic folder order. List incompatible files with a reason when helpful. Avoid scanning the whole disk.
- An explicit install downloads to a staging path on the same volume. Verify pinned bytes and the complete set before publishing the final directory atomically. One cooperative writer per asset identity prevents duplicate AHAMPO installs. Incomplete or corrupt files remain unavailable. Keep a valid installed set usable when a download fails. Setup can use one existing set and fetch only the missing one.
- Keep installed sets immutable and give the worker a stable reference for the lifetime of a load or take. Propose disabling changes while speech is active and waiting for the affected idle worker to exit before deleting or switching sets. An imported set can be detached without deleting the source. AHAMPO-installed shared sets can be deleted with confirmation that other apps may use them. External apps are free to ignore AHAMPO's locks. Report missing or changed files and avoid claiming their readers are tracked.
- Use vetted catalog paths. Reject traversal, unsafe archive entries and unexpected symlink targets. Validate borrowed Hugging Face snapshot links within the selected cache with provider-specific rules. Never delete through a cache link or rewrite another tool's index. Separate editable settings from installed files. A stock app start requires no connectivity check.

## Before application implementation

1. Run a read-only desktop capability probe on named browser versions and the local fixture. Exercise page selection, no selection, editable fields, focus takeover, and field or tab changes. Test the candidate write on expendable fixture text only.
2. Run the shortlisted speech tools against calibration audio and text. Compare first-audio delay, partial and final ASR, pause/cancel, phrase joins, memory while ready, and release on process exit. Measure with playback/capture independent of inference. Pin the winning files, license inventory and environments only after this step.
3. Finish the independent acceptance runner and fixtures. Qualify it with known-good and defective specimens. Freeze the tests, cases, inputs, expected results, thresholds, execution tools and environment model. Keep the approved digest or reference under independent control.
4. Build the app against that baseline. Run the same frozen cases against a recorded release binary. Check the implementation structurally as well as behaviorally.

The design review found three ownership risks to avoid: policy duplicated between capsule and worker, filesystem mutations while a worker loads a model, and a separate UI clock for Follow Along. The module layout above assigns one owner to each. Native browser compatibility, model latency, and quantitative budgets still need measurement.
