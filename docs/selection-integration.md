# How AHAMPO receives a selection

PopClip has a native overlay. Its developer says it uses macOS Accessibility where available and runs Copy as a fallback. That fallback can change the clipboard and is subject to focus and macOS permissions. [PopClip developer explanation](https://forum.popclip.app/t/popclip-modifies-the-system-clipboard-on-every-activation/3681) · [PopClip troubleshooting](https://www.popclip.app/kb/troubleshooting)

Easydict's open-source SelectedTextKit uses Accessibility followed by the app's Copy menu action in its automatic mode. Read Assist also snapshots clipboard items, waits for a fresh copy, and restores the snapshot if the clipboard has not changed again. These are implementations of the same desktop pattern. [SelectedTextKit](https://github.com/tisfeng/SelectedTextKit) · [Read Assist selection capture](https://github.com/ai-nuke/read-assist/blob/main/Sources/ReadAssist/SelectionCapture.swift)

Apple exposes the selected text attribute and a selection-change notification. An observer subscribes to an accessibility object in a specific process. Some objects cannot send notifications and the system-wide object cannot send them. A click-time lookup suits AHAMPO because it resolves the current selection before starting playback and does not depend on a background selection history. [Selected text attribute](https://developer.apple.com/documentation/applicationservices/kaxselectedtextattribute) · [Selection-change notification](https://developer.apple.com/documentation/applicationservices/kaxselectedtextchangednotification) · [Observer API](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification?changes=l_4)

Raycast exposes a command API that returns selected text in the frontmost app. Its public reference specifies the result and failure behavior. It does not describe the native implementation. [Raycast environment API](https://developers.raycast.com/api-reference/environment)

Read Aloud offers a browser context-menu entry. The corresponding WebExtensions API supplies `selectionText` when the user invokes a command for a selection. Native messaging can forward that text to a local app. Safari supplies its own native extension mechanism. [Read Aloud source](https://github.com/ken107/read-aloud) · [Mozilla menu event](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/OnClickData) · [Safari native messaging](https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension)

AHAMPO also offers **Read Selection in AHAMPO** through macOS Services. The foreground app supplies the selected text on the pasteboard for that invocation. AHAMPO passes it straight to the existing Kokoro player and keeps the draft separate. It does not read or write the general clipboard for the service. Use the browser’s application menu under **Services**, or assign a shortcut in **System Settings → Keyboard → Keyboard Shortcuts → Services**. Availability depends on the source app exposing its selection to macOS Services. [Apple Services guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/SysServices/Articles/providing.html) · [AppKit selection transfer](https://developer.apple.com/documentation/appkit/nsservicesmenurequestor/writeselection%28to%3Atypes%3A%29) · [Chromium Services implementation](https://chromium.googlesource.com/chromium/src/%2B/3a0f47bd212c5358f918d945ccd89d006b975469/ui/views_bridge_mac/bridged_content_view.mm)

The capsule checks the frontmost app when the speaker is clicked. It initializes Gecko's Accessibility tree when Firefox or Zen becomes active so the browser can track selections. Zen retained its old Accessibility text markers after a visible selection was cleared in a live test. For Gecko page selections, AHAMPO now also checks the browser’s standard Copy command for matching, freshly copied text. If Copy produces no text or the results disagree, the speaker uses the draft. A directly readable selection in an editable field doesn’t require this check. [Mozilla's Gecko initialization change](https://bugzilla.mozilla.org/show_bug.cgi?id=1845364)

Copy runs only in the verified foreground window and skips protected fields. It saves readable clipboard items and restores the snapshot when it detects no subsequent change. Clipboard writes by other apps can still race with Copy. On macOS 15.4 and later, the speaker uses Copy only with existing programmatic clipboard access. The explicit **Set Up Clipboard Access…** control in AHAMPO Settings explains the access used for selection and browser dictation. [Apple pasteboard access behavior](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum/default)

The capsule's direct lookup and its Copy menu fallback require a current Accessibility grant for the AHAMPO process. The browser's explicit Services command runs in the source app and passes AHAMPO its selection. Calling `NSPerformService` from AHAMPO requires supplying the text in advance. [Apple's Services documentation](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/SysServices/Articles/using.html)
